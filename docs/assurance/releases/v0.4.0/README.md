# v0.4.0 release assurance summary

This directory keeps a concise, durable summary of the v0.4 release assurance boundary. Executable evidence is generated by maintained repository workflows and stored as CI artifacts; this document does not duplicate transient run logs, workstation paths or construction transcripts.

## Release evidence model

A release claim is accepted only when it maps to a maintained runtime, negative/security test, integration path, operator surface, documentation and benchmark/recovery evidence where applicable. The Capability Acceptance Matrix is generated from registered evidence rather than a manually assigned maturity label.

Release assurance gathers same-revision reports and verifies their hashes before producing the release package. Missing, failed or skipped mandatory evidence cannot be replaced by a prose assertion.

Permanent evidence families include:

- core CI and browser/API/MCP integration;
- Team Context Node deployment and coordination;
- semantic/filtered retrieval and contextual/placement evaluation;
- Document Intelligence;
- concurrency and resilience;
- scale and enterprise-state bounded workloads;
- two-node federation;
- graph/code, temporal, workspace/team and retrieval diagnostic quality;
- Agent A/B and multi-arm agent arena;
- managed-Git/database/object restore and derived-state rebuild;
- release capability acceptance, parity/exclusion and limitation reports.

## Capability boundary

v0.4 productizes:

- versioned Knowledge Profiles and a Software Delivery Workspace Profile;
- Team Context, scoped agent principals, revision pinning, claims/fencing, offline snapshots and handoffs;
- federated specialized graph domains and deterministic Code Graph context;
- bi-temporal truth and stale-derived support validation;
- exact/lexical/semantic/graph/community retrieval with bounded context assembly;
- typed safe reasoning;
- Continuous Assurance and generic connector contracts;
- agent façade and human workspace surfaces;
- model residency policy, bounded federation and operational recovery.

Approved Markdown in managed Git remains canonical knowledge. Work coordination and derived graph/index state never become canonical by synchronization or ranking.

## Competitive evidence policy

Specialist systems are design inputs and, where feasible, executable adapters or benchmarks. AKP does not reuse README rankings or paper scores as current product evidence.

A reference feature may be recorded as implemented-equivalent, adapter-provided, benchmarked-not-adopted or deferred with a reason. An unexecuted comparator remains unmeasured.

The Code Graph path uses a pinned reviewed Graphify provider and keeps provider-derived edges distinguishable from human-reviewed knowledge and runtime evidence. Community/clustering remains owned by AKP's separate community retrieval capability rather than Graphify's clustering mode.

## Release limitations

- Vendor-specific live connectors beyond the generic connector/local-Git/webhook contracts remain optional.
- Registered public retrieval and agent corpora are small; results are not claims of broad domain superiority.
- Graphify language/extraction coverage is bounded by the pinned reviewed provider version.
- Federation evidence proves bounded team/organization behavior, not WAN or multi-region high availability.
- PPR is on-demand and cooperatively cancellable rather than a durable queued service.
- Late-interaction retrieval is not retained in the v0.4 production matrix.
- Optional model and document providers remain environment-dependent and may be explicitly degraded/unproven.
- Agent evidence records losses, invalid outputs and unsupported claims rather than manufacturing a winner.
