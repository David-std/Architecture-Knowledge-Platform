# P10 evidence matrix

This matrix is the working contract for P10. It separates implemented capability from evidence that has actually been executed. It is intentionally conservative: a synthetic harness does not establish retrieval quality, a deterministic agent harness does not establish LLM quality, and a passing component test does not by itself establish failure recovery for the full runtime.

The integrated P0-P9 baseline is `8c6051a82dbac618b63f5cc585b1c9742dece101` (`baseline/integrated-product-2026-09-14`). CI #355, Recovery #76, and Semantic Retrieval #5 were green on that baseline. P10 may change the branch only to add evaluation/assurance work or to repair a defect exposed by that work.

## Current P10 retrieval evidence

The first real-runtime Level B run is evidence of execution, not a production-quality verdict. It used the checked-in curated corpus and the pinned `intfloat/multilingual-e5-small` generation, exercised all nine required retrieval configurations, and kept `productionDefault.status` as `NOT_SELECTED`. Cross-vault isolation was checked during every configuration. The report is uploaded by the `semantic-retrieval` workflow as `runtime-retrieval-benchmark.json`.

## Claim discipline

P10 evidence must describe what was executed. A skipped external provider, missing binary format, synthetic scale corpus, or unregistered real corpus stays visible in the result. No benchmark may convert an absent dependency into a passing quality result, and no release document may claim production superiority from curated fixtures alone.
