# S2 — Reviewed original-SOURCE proposition service (opt-in)

**Status (2026-10-28):** evaluation-only, two-human review register; NOT an automatic natural-language truth oracle, Writer implementation, S2 gold, or authorization to release. S2 remains OPEN. E5 remains SHADOW; LAYERED, BGE, and bounded lexical recall stay OFF by default; S3–S5 remain BLOCKED and PR #38 stays DRAFT.

## Purpose and trust boundaries

The prior R5 exact proposition matcher knew how to compare a trusted `StructuredPropositionQuery` to a trusted SOURCE proposition but lacked a persistent production-shaped provider. This adds an opt-in, permission-checked provider for **pre-reviewed questions in any language**, including the EN/ES `requestedAnswerRole` contract. A proposal is NOT accepted evidence. A distinct authenticated HUMAN must review and approve it. No automatic LLM projection, model quote, title, score, or timing field grants approval. The human reviewers must inspect every question slot (actor, action, object, direction, negation, applicability date, conditions, modality, units) against the immutable raw source. The two-person procedure reduces self-certification but is not itself independent human gold or proof that the review was correct.

The resolver rechecks current vault and path grants, active document and document revision, active raw SOURCE and document/evidence link, current source-unit revision when present, exact query/excerpt SHA-256, an unambiguous UTF-16 passage in a bounded UTF-8 raw object, and a valid reviewer-supplied proposition with a quote wholly inside that passage. Invalid, missing, ambiguous, changed or unauthorized inputs return `null`; the LAYERED caller must abstain. No cross-revision cache and no downgrade to the semantic Reader when a governed proof is unavailable. This direct raw-text implementation intentionally **withholds OCR/PDF-derived and non-identically extracted Markdown** until their source-to-artifact transform is independently verified.

## Provisioning and lifecycle

Apply migrations up to `db/migrations/093_s2_reviewed_source_propositions.sql`. Supply existing `AKP_RAW_ENDPOINT`, `AKP_RAW_ACCESS_KEY`, `AKP_RAW_SECRET_KEY`, and `AKP_RAW_BUCKET` for the immutable source store. Set `AKP_S2_REVIEWED_SOURCE_ENABLED=true` only in an isolated, authorized evaluation environment. This flag alone does NOT enable LAYERED; explicit admission policy and a configured Reader are still required. If the flag is enabled without the raw store, startup fails closed. In an ordinary deployment the new endpoints and provider are absent.

1. A HUMAN with `knowledge:review` and `source:read` grants for the exact space, vault and document path submits `POST /v1/s2/proposition-reviews` with `spaceId`, `vaultId`, `documentId`, nullable `unitId`, `sourceId`, literal `question`, literal `excerpt`, `queryProposition`, and `sourceProposition`. The server pins SOURCE revision, object hash and exact raw excerpt; its response is only an ID and `PROPOSED` status. In a WHO question, `queryProposition.subject` must be empty and `requestedAnswerRole` is `SUBJECT`; the known object, predicate and all applicability qualifiers must be explicit. A WHAT question uses `OBJECT`, concrete known subject and an absent query object. The source proposition must supply the full subject/action/object and quote offsets relative to `excerpt`.
2. A **different** authenticated HUMAN with the same current scope independently verifies the whole claim and invokes `POST /v1/s2/proposition-reviews/:id/approve`. The server rereads the raw object and rejects changed or inaccessible evidence. The record becomes `APPROVED`; the runtime still verifies the source and authorization on every resolve. Two competing approved projections for the same question + SOURCE hit deliberately cause abstention until resolved; there is no timestamp-based winner.
3. `POST /v1/s2/proposition-reviews/:id/revoke` disables a previously proposed or approved record. This is not an irreversible delete and no new Source correctness is implied.

These endpoints must only be used with access-controlled original SOURCE and real human review. Automated parser outputs may be submitted as **unapproved proposals** by an authorized human, never auto-approved.

## Writer custody over authenticated HTTP

`POST /v1/s2/writer-claims/audit` requires `eval:run` and current `source:read`. Input is a **persisted, unexpired** `ContextPacket` ID and exact `packetHash`, the actual Writer `answerText`, and nonoverlapping, fully covering statement slices `{text,startUtf16,endUtf16,citationId}`. Accepted citation IDs `SEC1`–`SEC16` index the frozen order of that packet's sections. The server reloads the packet for its original user, checks current path/vault permissions, reconstructs hits from the stored sections, and resolves a **separately two-human-reviewed** question projection for each literal Writer statement. Nothing supplied by the client can supply `SearchHit` objects or `statementProposition` as semantic proof. The existing `auditGovernedWriterStatements` tests the original question and every statement through the SAME R5 structural owner. Its output is a redacted candidate, always `productionAdmission=false` and `releaseGateAccepted=false`. A current ContextPacket whose section is not a literal original SOURCE passage is withheld.

**Important limitation:** This is a real authenticated HTTP **audit of an externally supplied Writer result**, not a new Writer model invocation or proof that a particular remote provider was sent exactly the cited packet. The response therefore carries `fullAuthenticatedWriterRoundTripIndependentlyVerified=false`. Actual provider request/response custody and complete cold/warm HTTP+Writer timing still require a witnessed adapter test. A claim-sized statement with multiple assertions is not independently proven atomic just because it has one valid source quote; the audit explicitly retains `fullyAtomicIndependentlyVerified=false`.
