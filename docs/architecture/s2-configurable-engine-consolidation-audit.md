# S2 — consolidation and configurable-engine cutover audit (2026-10-28)

**This is an architectural disposition and implementation inventory, not semantic acceptance.**
PR #38 remains DRAFT; S2 OPEN, E5 SHADOW, bounded recall/BGE/LAYERED default OFF, S3–S5 BLOCKED. See the master evidence ledger §§1–93, `core-redesign-execution-spec.md` S2.1–S2.11, and the machine-readable `policies/s2-technique-disposition.json`.

## Finding: S2 is NOT already complete

A passing authentic-source HTTP test means that token authorization, vault scoping, immutable source rereads and explicitly reviewed claim custody operate. It **does not** mean that a new Spanish or English question can automatically be transformed into the correct actor, predicate, relation, negation, answer role, temporal scope or compound claims. Nor does it prove that a final LLM Writer response has every claim independently justified.

The historical 200 EN/ES/34-document **DEV** evaluation already isolated citation sufficiency and false abstention as major loss modes _after_ document retrieval. Its 209 citations and 58 affirmative Writer outputs have post-hoc, model-assisted judgments, not independent blind final-gate labels. The 48-case synthetic benchmark, 158 reviewer calibration pairs, 261-case Reader probes and 16-case four-model new probe are also DEVELOPMENT, for regression and falsification only. No corpus may be "re-blinded" after its outcomes are known.

**There is already a configurable engine.** Do not build another multi-engine pipeline. Make a _versioned experiment/deployment profile_ that configures the existing components, validates compatible combinations, freezes the profile SHA and records actual stage timings/decision reasons. Treat deterministic support as the paired baseline. `LAYERED` is an alternative admission owner, not an authorization bypass. QA/NLI and BGE may be independent diagnostic/ordering sidecars, not automatic corroboration votes. A configuration is _supported for controlled evaluation_ before being _eligible as a default_.

## Preserve, integrate, or retire — evidence-based disposition

The executable inventory lists **26 technique-level decisions** and **58 explicitly classified supplementary S2 modules/scripts**, including 69 `s2-*.ts` / `s2-*.mjs` modules and operator scripts across the audited trees. Run `pnpm s2:disposition:validate`; it fails on missing files, unclassified new S2 modules, duplicate techniques, missing source-ledger sections, invalid modes and unconnected documented flags. An inventory check is **NOT** proof that every import is live, a runtime was deployed, or an experimental algorithm generalized. Other non-`s2-` runtime code is included only where explicitly named.

**Preserve and test as operational options:** baseline deterministic and hybrid retrieval; authorized bounded unit recall and BGE ordering; SOURCE-governed relational/slot matching; reviewed-source opt-in + authenticated Writer claims audit; v5 Reader/LAYERED under strict scope and latency budgets.

**Keep evaluation-only until paired disjoint results prove a cutover:** independently source-bound SECTION, sentence windows, unique verbatim citation attribution, multi-claim/source portfolio, full-slot coverage, NLI and QA diagnostics, translation and self-consistency checks. Some are helpful _test instruments_, not new production requirements. Every product cutover must replace rather than permanently duplicate the same decision owner and preserve authorization and provenance.

**Do not reinstate rejected variations as hidden defaults:** mandatory Gemma proposition veto (ledger §67) disproportionately rejected correct Writer answers; mandatory Writer answer-slot prompt (§70) admitted additional negative cases. NLI/QA high-confidence scores do not prove answer entailment; BGE negative similarity must not set an evidence threshold. These experimental files/receipts may stay as falsification regressions until an explicit no-consumer cleanup, but their output must not be combined as multiple affirmative votes.

## Exactly what must be completed before S2 can close

1. **Single typed use-case owner (S2.1):** extract search/ranking/evidence selection from `apps/api/src/routes/search.ts` into existing Retrieval/application boundaries without changing HTTP/MCP behavior. Baseline and scope tests must agree before cutover.
2. **Real SOURCE-covered full chain (S2.4/S2.6):** frozen original bytes/current ACL + actual authenticated ContextPacket + pinned Reader response + **actual** native Writer response + each atomic claim/source passage/unknown answer-slot audit. Define fail-closed handling for missing reviews, conflict, stale source, empty proof and mixed-source statements. Do not turn manually prewritten test answers into generated answers.
3. **Controlled independent arms (S2.5/S2.9/S2.10):** under the same authorized pool, exact token and provider budget, run deterministic vs LAYERED Reader with explicitly recorded optional BGE/extra recall; only then A/B SECTION and exact source windows one factor at a time. Keep per-stage recall, correct answer coverage and loss reasons; do not assume 1/2/4 depth helps.
4. **Real paired corpus/outcome trial (S2.2/S2.3/S2.8):** separately independently selected and adjudicated publisher/source/relation-family-disjoint EN/ES positives and negatives, including actor, inverted relation, time/version, negation, unit, condition, contradictory source, long answer, multiple claims, authorized/denied vault and PDF/OCR degradation cases. The existing 240-seat template is **empty**, not acceptance gold. Score exact target-model input tokens, baseline Obsidian/manual, full and compact ContextPacket, cold/warm whole-route latency and human audit of full Writer answer. Preregister evaluation before first inference.
5. **Release/regression gate (S2.7/S2.11):** restore all same-SHA CI (including local/Node24 integration), real ACL/path/revision checks across graph/expanded/continuation paths, provider abort/degradation and no silent fallback, source-cluster uncertainty, rollback and license review. No production default promotion unless the independent holdout passes.

Historical provisional **minimum gates** remain evidence precision **≥80%** and simple Wilson95 lower bound **≥70%** (plus cluster- and stratum-aware uncertainty), false admissions **≤10%** **and no worse than deterministic**, complete HTTP p95 **≤25 seconds**, degraded calls **≤5%**, no correctness or valid positive-answer coverage regression. A stronger operational goal (for example precision ≥90% and FAR ≤5%) is worth optimizing **on future DEV data**; it is **not an achieved result or a substituted acceptance gate**, and post-hoc threshold tuning on the final independent holdout is prohibited.

## Same-SHA CI caveat and immediate repair

Remote CI on `63727cb0` passed the new isolated original-SOURCE integration on Node24, then failed in the **broad API integration matrix** because Vitest executes the callback of `describe.skip` while collecting tests; the opted-out S2 test file constructed a MinIO store prematurely and encountered an invalid absent URL. The code fix moves DB/object-store/Fastify creation into enabled `beforeAll`, so a skipped test creates no connections or side effects. Verify a no-flags test run, genuine disposable-DB run, full API integration and same-SHA clean CI; do not report green until they pass.

**Decision:** the architecture and 93 prior experiment sections have not become a validated product by accumulation. Preserve the successful components through one ordered, configurable, measurable pipeline; leave rejected results available as adversarial tests; close S2 **only after** the independent new-answer evaluation and full Writer/source validation.
