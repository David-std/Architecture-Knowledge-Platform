# S2 — Source-span holdout and evaluation protocol

- **Stage:** S2 in progress, baseline S1 code `3969cd6f11bbd247981ccf630b2a7469ba78d306`.
- **New frozen synthetic holdout:** [S2 source-span cases](../../evals/registered/s2-source-span-holdout.json), frozen 2026-10-13: 4 domain-disjoint documents, 24 text units, 48 labelled cases: 24 positive, 24 no-answer, balanced 24 English/24 Spanish. Every domain has 3 positive and 3 negative cases per language, with source-unit identifiers and literal answer-bearing spans rather than just document-level oracles.
- **Frozen-byte check:** Git blob SHA-1 `a61a24df46c0351115cd09e079ae0d8383033082`, verified in CI by `node scripts/validate-s2-span-holdout.mjs --self-test`. The validator checks hashes, exact quote substrings, source IDs, strata, pre-registered thresholds and mutation resistance, then emits SHA-256 over each ordered source-unit payload. This is a structural fixture validation, **not a retrieval or model-quality result**.
- **Independence boundary:** these four new synthetic domains are separate from the previous eight-domain evidence-admission corpus and frozen F3 studies, but are **author-constructed, not independently human-adjudicated or blind**. No private documents or customer information are included. Do not tune the source-specific runtime on the answers or labels in the public holdout.
- **Experimental controls before comparison:** fixed source digests, ACL/vault scope, approval and revision, query order, model/tokenizer exact versions, budgets, timeouts, index version, deterministic seed, identical authorized candidate pool for head-to-head readers and independent human adjudication of positive and negative ground truth.
- **Distinct measurements:** answer-bearing unit Recall@k before admission; exact-source-span admission precision; no-answer/adversarial false-admission rate; final answer grounded correctness and abstention (same agent/model); p50/p95 latency, errors, real reader calls; then paired manual-search/Obsidian baseline versus full vault, full and compact ContextPackets, and selected excerpts.
- **Token comparison:** count exact input tokens with one pinned target-model tokenizer (the existing `packages/retrieval/scripts/context-tokenizer-baseline.ts` is a starting mechanism); report mean/median/p95, source/citation survival, task success and actual cost/latency. `char/4` is only an approximation.
- **Pre-registered provisional gate, NOT achieved:** evidence precision ≥0.80, simple Wilson95 lower diagnostic ≥0.70 plus stratification-aware uncertainty, false admission ≤0.10 and no worse than deterministic baseline, p95 ≤25 s, degraded call rate ≤5%, no loss of answer correctness. Do not infer universal precision or zero FAR from 48 synthetic cases.
- **Open work:** S2.1 typed operation unification, S2.3 real paired manual baseline, S2.4–S2.11 semantic error taxonomy/reader comparisons/token measurements/permission checks and S2 final gate. No retrieval policy, provider, embedding or production default changes in this commit.
- **Pure scorer (first S2.4 instrument):** `packages/evaluation/src/s2-source-span.ts` accepts recorded ranked source-unit IDs, exact UTF-16 quote offsets, admissions, reader degradations and latencies. It reports separate gold-unit Recall@1/5/10, strict _gold-quote coverage_ (not human semantic precision), no-answer false-admission rate, Wilson95 simple diagnostics and p95. Without live observations the result is `NO_OBSERVATIONS`; with missing questions `PARTIAL_NOT_GATEABLE`; even complete synthetic observations are `MEASURED_NOT_GATEABLE` pending independent adjudication. Exact input tokens remain `null` unless every observation provides a pinned tokenizer revision. No ranking or production admission logic was changed.
- **Recorded run CLI:** `pnpm exec tsx scripts/s2-score-observations.ts --observations measured-run.json --output reports/ci/s2-span-observations.json` requires an explicitly provided observation set with exact source digests, scoped configuration, executed Git SHA and input tokenizer evidence. Partial runs require `--allow-partial`, empty runs fail, and every report declares `gateAccepted: false`. It cannot fabricate AKP/Obsidian gains or approve an unadjudicated holdout.
- **Real database retrieval baseline:** `apps/api/test/s2-source-span.integration.test.ts` creates a disposable PostgreSQL database and four separate synthetic source vaults with 24 passage units. The maintained `queryKnowledge` operation executes all 48 frozen questions on exact+lexical channels; its observed ranked unit IDs, candidate pool size, warnings, latency and vault-scope constraints are recorded in `reports/ci/s2-postgres-retrieval-baseline.json`. The test fails on cross-vault results and cleans up. This **direct test-only knowledge projection is not a raw-source ingest/review E2E**, and its controlled lexical profile is **not** proof of the current full hybrid model configuration. All semantic-admission, final-answer, model-token and Obsidian metrics remain null/unmeasured. No quality threshold or release promotion is asserted.
- **Scope-integrity assertion:** the S2 recorded-observation scorer now rejects out-of-vault, unknown or duplicate ranked units for this single-source-per-question holdout rather than silently rewarding or discounting them. The PostgreSQL integration also fails hard if the retrieval function returns a different vault. This verifies the scorer/harness boundary only; it is not proof that every graph, aggregate or continuation path has passed S2.11.
- **S2.5 pinned-provider shadow arm (not deployment selection):** `.github/workflows/semantic-retrieval.yml` runs the frozen 48 cases on exactly the existing `queryKnowledge` operation in two sequential profiles: `exact+lexical` versus `exact+lexical+vector` with the already pinned local multilingual E5 provider and real activated Postgres embedding generations (six source units per vault). The new guarded integration test reuses the same synthetic fixture, vault ACL, sources and query order; records English/Spanish Recall@1/5/10, candidate IDs, provider channels, warnings, latency and generation/model revision in the archived `reports/ci/s2-multilingual-shadow-baseline.json`. It rejects unmapped/out-of-vault candidates and silent vector unavailability. **No source gold labels are used to tune a model or policy**, and there is no minimum accuracy assertion. Both arms leave admission, answer correctness, manual baseline, true model-token savings and final S2 acceptance explicitly unmeasured. Sequential duration includes cache/warmup/order effects and must not be taken as a fair final speed comparison.
- **S2.6 deterministic passage-support shadow diagnosis:** the same pinned E5 comparison also reuses `assessRetrievalAnswerability` on the authorized post-rerank candidate pool, recording per-unit support reasons, cue coverage, positive answer-bearing support and the count of no-answer queries for which _some_ candidate passes the deterministic support probe. This probe is not an independently adjudicated sufficient source quote, not production reader admission, and not final-answer FAR. Its negative-risk count is reported separately without changing any admission policy. The semantic workflow now supplies `AKP_S2_BRANCH_HEAD_SHA` from the PR head for artifact provenance in addition to GitHub's temporary merge checkout SHA.

- **S2 reviewer packet source authenticity (test-only, not an admission gate):** `scripts/validate-s2-adjudications.mjs` now loads the frozen corpus independently, verifies the pinned Git blob SHA-1 and source-document SHA-256, and reconstructs the question/source/unit identity and candidate key for **every one of the 288 authorized reviewer excerpts**. Each exact UTF-16 excerpt must equal the corresponding source-unit slice; a self-consistent forged passage plus a recomputed passage hash is still rejected. The CLI maintains six independent provenance-mutation self-tests in addition to seven annotation-integrity mutations; the semantic CI workflow fails closed if the source binding is absent or fewer than 48 questions/288 source excerpts are verified. These checks do not reveal author gold spans to reviewers, adjudicate answerability, prove reviewers were independent, or measure evidence precision/FAR. Reviewer CSVs remain external; human-origin and independence are not established by schema checks.

- **S2 independent reviewer disagreement workflow (tooling, no human ratings fabricated):** after the two complete source-bound reviewer CSV submissions pass validation, `node scripts/validate-s2-adjudications.mjs --packet <packet.json> --packet-sha256 <sha256> --reviewer-a <first.csv> --reviewer-a-id <id> --reviewer-b <second.csv> --reviewer-b-id <id> --disputes-output <blank-disputes.csv> --output <integrity.json>` exports **only genuinely disputed pairs**, without either reviewer's verdict or any author gold. Exact label disagreements and different quote-offset judgments require a third distinct reviewer; do not count majority consensus or silently choose the earlier reviewer. To validate a third submission, add `--resolution <third.csv> --adjudicator-id <third-id>`: it must annotate every disputed pair exactly once, with source text/hash/UTF-16 offsets unchanged, and must not include already-agreed or foreign pairs. Its reported status remains `THIRD_SUBMISSION_VALIDATED_HUMAN_ORIGIN_UNVERIFIED`, and S2 gate flags remain false/null pending independent human-origin verification and a separate real reader admission/answer evaluation. When no disputes exist, no third review is required.

- **S2 reviewer calibration v1.1 (2026-10-17, post hoc):** The two original source-bound reviewer submissions have **arrived** externally and passed structural validation (288/288 each), but remain uncommitted; person-to-person procedural independence cannot be proven from the files. Reported 145 category disagreements and ten quote-offset disagreements (155 pairs total), plus three consensual `CONTRADICTS` labels that merit separate missing-measurement controls. The adjudication rubric is now explicitly frozen **after** observing these disagreements: see [post-hoc reviewer calibration rubric](./s2-review-calibration-rubric.md). The third-party reviewer kit is **external/offline**, split into blank Set A (155 official disputes) and blank Set B (three consensus controls), with distinct CSV outputs. Original input labels and source corpus are not modified. These are **calibration data**, not a newly blind preregistered performance evaluation; admission and gate flags remain false or unmeasured.

- **External evaluator blind delivery (2026-10-17):** to prevent revealing which entries are disagreements or consensus controls through filenames or kit documentation, the reviewer receives **one** offline HTML form containing **158 source-bound question/passage pairs mixed in a deterministic order**, without prior votes, author gold, or set-membership metadata. The reviewer returns one 158-row CSV. A separate coordinator-only Python splitter validates fixed frozen-packet SHA, 158 exact pair identities, source bytes/hashes, categorical completeness and UTF-16 quotes, then writes precisely 155 official disputed-pair annotations and three extra consensus-control annotations with distinct digests and no overwrite. The 155-row file alone is passed to the existing `--resolution` validator; the three controls are adjudicated separately. Chromium download/quote interaction tests and six malformed-input rejection cases passed locally; the script and human CSVs remain external and uncommitted. This is partial answer-label blinding in a public, author-constructed calibration set, not independent blind final evidence.

- **Postcalibration shadow instrumentation (2026-10-18, no quality result):** the actual `/v1/search` and `/v1/context` answerability paths now accept an explicitly injected, redacted `s2AdmissionShadowSink`. It distinguishes application admission from a shadow verifier decision, records scoped candidate/quote digests with checked excerpt-relative UTF-16 spans and admission-only timing, and never changes the answer. Tests cover malformed surrogate offsets, foreign vault candidates and callback isolation. No configured semantic reader, full source-rebinding, response p95, FAR, final answer or manual baseline has been measured on an independent set. Freeze the [new holdout preregistration](./s2-postcalibration-preregistration.md) _before_ collecting new questions or selecting reader thresholds.
