# S2: question role, full declarative claims and source-bound semantic verification (23 Oct 2026)

**Scope:** development-only experiments and evaluation interfaces on PR #38. This report is not an S2 gate decision or a production authorization. The original E5 HTTP/24-case admission experiment is **not rerun here**. Two source-disjoint-for-DEV families and the already captured private originals were used. The author constructed or previously inspected their labels; none is an independently adjudicated holdout. S2 OPEN; E5 SHADOW; S3–S5 BLOCKED.

## Observed failures and hypothesis

An exact SHA/UTF-16 citation establishes attribution, **not** that the answer is of the requested type or that its complete subject–predicate–object/condition/negation relation is supported. A structured JSON writer can produce a syntactically valid unsupported answer; an isolated role judge can falsely reject supported answers. These are different errors and require separate traceable observations, not one lexical threshold.

The experiment retained the raw response bytes and source hashes; subsequent runs have separate immutable output directories. No source labels were included in inference prompts. Scores derived after capture are marked as author-labeled and not independent.

The earlier native-writer v1 returned only **3/8 structurally valid** Qwen responses; the generic v2 JSON contract produced **8/8 for each of two models**. This improvement is purely syntactic. On MDN the raw answer/no-answer error diverged sharply across writers; writer agreement is not evidence of truth.

The preliminary question-role model classified supported answers as mismatches. Treating its judgement as an authoritative gate eliminated valid attempts **before F3**. The evaluation bridge therefore keeps the role decision as **diagnostic** while projecting the original question plus the proposed answer into a complete declarative hypothesis. Source-independent projection is never evidence: it must echo the proposed value **exactly**, preserve the question relation, and then pass original-bound F3 and a separate whole-answer check. The model can still hallucinate a projected relation. On the source-disjoint MDN cases F3 proposals were **0/8** positive, so this is **not a solved sufficiency problem**.

## Implemented, opt-in evaluation contracts

- `prepareS2QuestionAnswerClaim`: independent revision-identified answer-role probe and declarative-claim projector run concurrently; a role mismatch is recorded, not a final veto. Exact answer echo and bounded, nonempty declarative proposition are mandatory. All outputs explicitly mark semantic/source entitlement and production admission **false**.
- `bindS2VerbatimWindowQuote`: rebinding from frozen source windows to an F3-compatible literal source quote; validates SHA, original UTF-8, document frame, UTF-16 surrogate boundaries and uniqueness, and trims only _exterior_ window whitespace. No fuzzy quote reconstruction or trust promotion.
- `checkS2SourceClaimActorBinding`: checks a model-proposed grammatical source actor and answer actor **only** when both are unique, verbatim substrings of the respective inputs. Mismatch is diagnostic negative evidence; match is not entailment. A short, ambiguous or absent actor remains indeterminate. This is opt-in; Qwen extraction's all-indeterminate run means it must not be treated as a generic production filter.
- Eight role-claim tests, sixteen original-window tests and four actor-binding tests: **28/28** passed in focused execution. No production HTTP search behavior, policy thresholds or default gates were changed.

## What this does not establish

The source-disjoint MDN slice contains only two editorial families, four positives and four negatives, author annotations and **no independent adjudication**. The relation benchmark is small and synthetic, previously inspected, and known to this project. ONNX direct claim entailment is not answer adequacy to the question. F3 and whole-answer evaluation did not produce a qualifying MDN answer, hence whole-answer sufficiency and final HTTP false-admission rate remain **unmeasured**, not zero. An early diagnostic-stage model output of `CONTRADICTS` is not proof of logical contradiction without original context. A falsified actor/span cannot grant authorization. Absence of false support in eight negatives has broad uncertainty; no S2 threshold or provider is promoted.

For an independent gate, use an externally frozen EN/ES corpus with different source/editorial families and both supported and unsupported relation types, original authorized HTTP path, measured ranking→admission→writer→claims→F3→whole-answer stages, byte-exact citations and UTF-16 replay, both false admissions and false abstentions, latency p95 and label blindness. Run multiple models under the **same** sampling plan and do not modify policy on the held-out responses.

## Third-model transfer: Gemma3-4B (same-day, no threshold changes)

To test whether the preceding effects were Qwen/Llama artifacts, a third **digest-pinned** Ollama model, `gemma3:4b` (`68ceab7e468a31c988b44d5a4984a0e21f58c4f7158c6ce29c1804babac38df7`), was evaluated against the **same previously frozen sources and questions**. - F3 on the 16 known adversarial relations: **8/8 supported positives; 2/8 false supports**, again exactly **B4 and C4**. The errors were correlated across generative models, so model voting alone is not a sufficient relation gate.
- Gemma's separate literal actor extraction returned mismatched, original-bound subjects for both **B4 and C4**; the **conjunction F3 SUPPORTS + no explicit actor mismatch** retained 8/8 positive candidates and 0/8 false-support candidates _on this exposed development slice_. Four actor cases were indeterminate, not counted as actor matches. Unlike entailment, this is a narrow structural diagnostic. The result has no reliable independent-domain estimate and is not a production gate.
- On the 8 public MDN EN/ES writer questions, the **unchanged generalized JSON writer schema and instructions** produced only **6/8 structurally valid outputs**; among four positives there were **3 structurally valid non-abstentions**, and among four negatives **2 structurally valid non-abstentions**. Thus the favorable structural actor result on synthetic material **did not** translate into a generally reliable answer writer. Neither syntax nor a single-source citation is a factual adequacy guarantee.

## Correction of false contradictions and multi-window cost (23 October, follow-up)

The first original-bound Qwen run after the multigranularity bridge accepted only **1/3 author-positive claim candidates** (ES01) and 0/4 author-negative candidates. EN01 was spuriously labeled `CONTRADICTED` by a reader even though the original MDN source explains that Cache-Control directives are case-insensitive. That NLI output is not a factual contradiction. Seven exposed-development questions required **43 model calls** and approximately 189,179 ms cumulative model call time (not HTTP p95). Raw, pre-oracle observations: `.work/s2-mdn-new-family-20261023/RUN-MDN-REAL-MULTIWINDOW-F3-DEV/UNSCORED.json` SHA `4177bed6f254492275ede25f04889f50929f7623691e30bb6e1fcaab81be299c`; posthoc SHA `60ea57f90183b83e4289dc867af14aa6a6abfd75adf20a8a6d1a8df486d93c26`.

The implementation now makes three general, shadow-only architectural corrections rather than tuning labels or a model score:

- **Typed negative semantics.** A model's `CONTRADICTS` at the _question relevance_ stage is mapped to `INSUFFICIENT`: an interrogative question is not a refutable factual claim. The raw stage verdict remains inspectable. A claim-entailment `CONTRADICTS` is retained as `CONTRADICTION_PROPOSED`; a support/contradiction collision is `CONFLICTING_PROPOSALS`, not a certified logical contradiction or an authoritative negative. This does not turn contradictions into support.
- **Overlapping evidence reduction.** Dual sentence/Markdown candidates are rebound to the frozen original SHA/UTF-16 positions before being compared. A fully contained span is redundant to a longer source-bound window, so it is pruned; partially overlapping windows are preserved to avoid dropping facts, conditions or negations not shared between them. The existing source, quote, token and authorization checks remain fail-closed.
- **Single-call paired observations.** `createS2PairedSemanticPorts` projects a single structured provider response into distinct question-relevance and complete-claim entailment ports, reusing a bounded, content-addressed in-flight/completed inference. Cache keys include question, complete claim, source ID, revision SHA, literal quotation and exact UTF-16 boundaries. Failed calls are evicted. **The two decisions from one model are correlated, not independent corroboration.** Existing F3 checks each returned reason and source-bound evidence span; neither this adapter nor a proposed `SUPPORTED_CANDIDATE` grants production admission.
- **Optional discovery short circuit.** `FIRST_SUPPORT` is an opt-in exploratory setting to stop model calls after a first candidate. It must prevalidate all supplied source windows before _any_ call, explicitly reports unchecked windows and `exhaustiveEvidenceScan: false`, and cannot certify contradiction absence or answer-level completeness. The default remains `EXHAUSTIVE`.

These changes intentionally do **not** modify the production admission pipeline, policy thresholds, authorization constraints, active E5 defaults or S2 release gates. Reproducibility of subsequent paired-model runs must use fresh, immutable output directories and compare the same frozen claims/sources. Any observed speedup combines pairing, candidate containment and prompt changes; do not attribute it solely to one component or claim statistical accuracy without independent labels. Validation status and measured outcomes should be recorded after the completed final run.

### Result of the real paired-reader shadow run (23 October; post-capture score)

A separate capture compared the now-available opt-in paired reader against the existing two-model-stage Qwen run, using **exactly the same seven frozen Llama writer claims and two original MDN source files**. Candidate selection was modified by containment pruning, and the prompt/structured output were modified from separate question/claim prompts to one pair; results therefore do **not** isolate the effect of the memoization adapter alone. The author labels were opened **after** provider bytes were frozen. The original source files were previously inspected by this project; they are not an independent holdout.

| Dev measure                                 | Two-stage old trial | Paired new trial |
| ------------------------------------------- | ------------------: | ---------------: |
| Full cases                                  |                   7 |                7 |
| Author-positive claims                      |                   3 |                3 |
| Positive source-bound support proposals     |      **1/3 (ES01)** |          **0/3** |
| False support proposals on author negatives |                 0/4 |              0/4 |
| Actual Qwen calls                           |                  43 |               26 |
| Sum of provider-call wall durations         |          189,179 ms |       130,626 ms |
| Candidate windows evaluated                 |                  39 |               26 |

**Decision:** Do not promote the paired reader to the default semantic engine. Its ~39.5% fewer calls and ~31% lower cumulative call duration are **not** worth the 1/3→0/3 loss in the already small positive set. No independent label, complete-answer FAR, HTTP p95, source admission or production quality gain is established. Direct F3 question-stage `CONTRADICTS` is now an explicit insufficient-relevance observation, while uncorroborated claim contradictions remain model proposals; this prevents overreporting logical conflicts but does not manufacture support.

For subsequent engineering, keep **specialized question focus and independent full-claim NLI** as the higher-recall experimental path; investigate better source contextualization, claim projection fidelity, and independent verification of the answer type before moving to new family-disjoint benchmark cases. Optimize latency only after preserving both positives and negatives and checking claim-level error reasons.
